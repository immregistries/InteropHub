# H5.1: Review Fixes (InteropHub)

Continue on `feature/h5-private-hosting` in your worktree. G reviewed `8b16f3b` against the code. The storage path, HTML rules, view servlet headers, CSRF, permission checks, schema, and tests are accepted, and the contract changes (7.4, the 5.1 `hosting` field, the `versions` scopes) are approved as written. Two fixes are needed before Gate 3H; both are cases where the design says the reader should get somewhere and today they do not.

## 1. Signed-out readers must come back to the guide

`GuideViewServlet` sends a signed-out reader to `/home`. After signing in they land on the home page, not the guide. Hosted guides will be shared by link (email, meeting notes), so this is the main way a reader arrives. Design 3.3 and your own contract text say "go to sign-in and back".

- Carry the guide URL through sign-in so that after the magic link is used, the reader lands on the same `/guide/view/{documentKey}/{label}/` URL (query kept). It must work when the magic link opens in a new tab, so carry it on the magic link or login code rather than only in the session that requested it. `MagicLink` and `AuthLoginCode` already have a `returnTo` field used by the external-application flow; reuse what fits, but keep the external flow's behavior unchanged.
- Accept only a relative path under the context path that starts with `/guide/view/`. Anything else is ignored, and the reader goes to the normal post-sign-in page. No open redirect.
- If the reader turns out not to have access after signing in, they get the usual not-found page, as today.
- Tests: the return path survives the magic link; an absolute URL, `//host`, a path outside `/guide/view/`, and an encoded variant of each are all ignored; the external-application return flow still passes its existing tests.

## 2. Version labels must be able to sign in to comment

Only `…/latest/` and `…/main/` are allowlisted, so a reader on `…/v0.3.0/` who selects "Sign in to comment" fails the `return_to` allowlist check. Fix it so every label of a `HUB` document can complete the guide sign-in, without registering each label as a guide URL:

- Keep `latest/` and `main/` as the document's guide URLs (`/guide/open` default unchanged).
- Make the document's allowlist row the prefix `{hub}/guide/view/{documentKey}/`, which the existing prefix matching (`AuthFlowService.matchesAllowedBase`) already accepts for every label, and remove it the same way when the document leaves `HUB` or becomes inactive. Do not allowlist `{hub}/guide/view/` for all documents.
- Update contract 7.4 to say so.
- Tests: a `return_to` on a version label of a `HUB` document passes; the same path for a different, non-`HUB` document key fails; switching to `EXTERNAL` removes the row.
