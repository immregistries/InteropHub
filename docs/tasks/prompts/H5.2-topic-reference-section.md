# H5.2: Topic Reference Section on the Topic Page (InteropHub)

**Status:** Approved by the product owner 2026-11-10 (right-rail card removed for everyone; at most two guides shown per topic)

Continue on `feature/h5-private-hosting` in your worktree, so this ships in the same release as H5. Gate 3H's local part has passed; this is a UI change on the topic page only. No schema, API, or contract change.

## Why

The right rail of `/es/topic/{id}` carries a "Topic Reference comments" card (`TopicReferenceCommentsPanel`, rendered in `EsTopicDetailServlet` inside `<aside class="aira-right-rail">`). It is too cramped for guide links, counts, and comments, and it shows to every signed-in viewer. The product owner wants a bounded section in the main column instead, shown for now only to people who can edit the topic.

## What to build

### 1. Remove the right-rail card

Stop rendering `TopicReferenceCommentsPanel` in the right rail, for everyone. Remove or replace the class; do not leave dead code.

### 2. New section in the main column: "Topic Reference"

Place it after the Overview card and before the Meetings card (the Meetings card is only rendered when there are meetings; the new section must not depend on it). Use the same `aira-section-card` shell as its neighbours.

**Who sees it (temporary):** only viewers for whom `TopicSpaceAccessService.canEditTopic(viewer, topic)` is true (champions, admins, and anyone else who can edit). Put the rule in one method, for example `TopicReferenceSection.visibleTo(viewer, topic)`, with a comment that it will later widen to `canViewTopic`. Build the section so that widening it is that one change. The management links (below) must stay behind `canEditTopic` even then.

**When it is shown:** only when the topic has at least one active guide document. With none, render nothing; editors register a guide from the topic management menu as today.

**Header:** title "Topic Reference", a small neutral badge "Editors only", and on the right two links: "Manage comments" (`/es/topic-guide-comments/{topicId}`) and "Guide settings" (`/es/topic-guide/{topicId}`).

**Body, per active document** (normally one; show at most two, and if there are more, one line "N more guides" linking to the guide settings page). Each document block has four parts, top to bottom, with fixed limits so the section never grows with the data:

1. **Guide links.** The document title, then a hosting badge: "Hosted on InteropHub" (`HUB`) or "Published externally" (`EXTERNAL`). Then the version links as compact buttons or chips:
   - `HUB`: from the hosted versions (newest upload per label). `latest` first as the primary link, then `main`, then the newest three `v…` labels by upload time, then "+N earlier" linking to the guide settings page. Each links to its `/guide/view/{documentKey}/{label}/` URL.
   - `EXTERNAL`: the registered guide URLs with their labels, in registration order; the first is the primary link. At most five, then "+N more" to the guide settings page.
   - "Open the guide" behaviour stays the same: the primary link may go through `/guide/open?doc=…` so it keeps its fragment handling.
   - If the topic's space is PRIVATE and the document is `EXTERNAL`, show the existing "private topic with a public guide" warning here (one line, suggesting hosting on InteropHub).
2. **Counts.** One row of four small figures, each linking to the Manage comments page with the matching `show` filter and `document` key:
   - **Open**: threads with state `OPEN` (no disposition yet) → `show=OPEN`
   - **Disposed**: state `DISPOSED`, not yet closed → `show=DISPOSED`
   - **Flags**: active review flags → the guide with its first flagged anchor, or Manage comments
   - **Closed**: state `CLOSED` → `show=CLOSED`

   Followed by one line: "Last activity {date} · {N} comments and {M} replies from {P} people in the last 30 days". Count only non-deleted, non-withdrawn comments. Leave out the 30-day clause when it is all zero.
3. **Needs attention.** Up to five `OPEN` threads, most recent activity first. Each row: a one-line excerpt (about 100 characters, single line with ellipsis), then a meta line "author · date · N replies", linking to `/guide/open?doc=…&comment={id}`. Below the rows, when there are more: "View all {N} open comments" to Manage comments with `show=OPEN`. When there are none: "No comments are waiting for a disposition."
4. **Flagged for review.** Only when there are active flags: up to three, each "anchor · note excerpt · date", linking to `/guide/open?doc=…&anchor=…`. More than three: "+N more" to Manage comments.

**Layout.** On wide screens, parts 1 and 2 sit on top as a compact header band, with parts 3 and 4 as a list below. On narrow screens everything stacks. Reuse the existing shared classes (`aira-section-card`, `aira-chip`/`aira-button--small`, `aira-badge`, `aira-meta`, the list row styles used by the old card). Read `docs/aira-web/README.md` before adding CSS; if a small stat-figure style is missing, add it locally and name it in your report as a candidate for `aira-web`.

**Times.** Show dates in the readable form already used on the topic page (for example "Nov 9, 2026"), not ISO strings.

### 3. Data and cost

- Get counts with aggregate queries (one per document) rather than loading every comment. Add a small read-only method to the comment store or service for this; follow the DAO-per-table pattern.
- The section must not slow the topic page noticeably: at most a handful of queries per document, no per-row queries.
- If anything in the section fails, log a warning and render nothing, as the old card did. The rest of the page must still render.
- Never show stored file `public_id`s or storage URLs.

### 4. Also fix (Gate 3H finding 3H.1)

On the guide settings page (`/es/topic-guide/{topicId}`), show hosted version upload times in the same readable form, not raw ISO UTC.

## Tests

- Section visible to a topic editor; not rendered for a viewer who cannot edit, for a signed-out visitor, or when the topic has no active guide.
- `HUB` and `EXTERNAL` documents render their version links with the limits above ("+N earlier" appears past the limit).
- Counts match a fixture with comments in each state, including deleted and withdrawn ones that must not count.
- At most five "Needs attention" rows and three flags, with the "View all" and "+N more" links.
- The right rail no longer contains the Topic Reference card.
- `mvn test` passes.
