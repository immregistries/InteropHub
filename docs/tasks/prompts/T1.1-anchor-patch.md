# T1.1: Anchor Patch Release v0.5.1 (content-publishing-templates)

You are working in `C:\dev\writing\content-publishing-templates`, on `main` at `v0.5.0`. Same rules as `T1-anchors.md`: read `AGENTS.md`, public repository, no third-party Python dependencies, run `validate.ps1`.

The first project to adopt `v0.5.0` found two problems. Fix both as a patch release.

1. **Extra blank lines in the reading copy.** `build_core_markdown.py` removes an anchor line but leaves the blank line around it, so a source with a blank line before and after each anchor gets two blank lines in a row in the reading copy. Each anchor adds a noisy line to the generated file's diff. Remove the anchor so that the blank lines around it collapse to one, and the reading copy is byte-for-byte what it would be with no anchor. Leave fenced code untouched, as now. Add a validate check that a fixture file with anchors produces a reading copy with no run of two blank lines that the source without anchors would not have.
2. **Duplicate IDs that were already there.** The new duplicate-ID check correctly found an existing collision in a project: a `## Representations` heading in one file and a separate file whose section ID is also `representations`. Builds before `v0.5.0` silently produced two elements with that ID. Keep the build failure, but:
   - make the error message say how to fix it: give one heading an explicit ID, for example `## Representations {#related-representations}`, and note that a heading ID is also an anchor name, so it should be stable;
   - say the same in the Review anchors section of `guidance/Conventions.md`;
   - add to the CHANGELOG that upgrading to `v0.5.x` may surface an existing duplicate ID, with the fix.
3. CHANGELOG entry `v0.5.1`. Do not tag.

Report back the files changed and the exact new error message. Do not commit, tag, or push.
